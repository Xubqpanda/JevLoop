# log/ —— 每次运行的原始产物

**不进 git。** 这里的东西是本地产物,`clone` 下来是空的 —— 这是有意的,
和 `dataset/` 一个道理。

```
log/
├── <数据集名>/<臂名>/<时间戳>-seed<N>/
│      cmd.txt        实际跑的命令（**复现的第一手材料**）
│      meta.json      run 的全量记录（见下）
│      events.jsonl   ★ 一条事件流:模型调用 / 判定 / 工具 / 答案,各一条
│      results.jsonl  逐题的判分与账目
│      exit.json      退出码与完成情况
└── _superseded/      改名或改格式**之前**的跑 —— 见下
```

## ★ 判据:什么样的 run 能进表

**看 `meta.json` 字段齐不齐。** 齐全的至少能回答三个问题,缺一个就不能引用:

| 字段 | 回答什么 |
|---|---|
| `dataset_version` | 这题是**哪个版本**的（`openai/gsm8k@59ec1b7f9357c7a2`）|
| `split` | 哪个划分 |
| `generator` | 哪个模型、哪个版本跑的 |
| `task_count` / `commit` | 多少题、哪份代码 |

**缺任何一个 = 这次跑的数不能进表。** 不是「不太严谨」——是**查不到出处**。

`python3 -m experiments.scripts.check` 会机械地验这一条（它是一道**门**,
不是报告）。历史存量记在 `scripts/check-baseline.json` 里,**只能变小**。

## `_superseded/` —— 改名或改格式之前的跑

这里的目录**不可引用**,原因有两个,都不是「跑得不好」:

1. **改名漂移**:那时数据集叫短名（`bfcl-simple`）,现在注册表里是
   `bfcl-v3-simple`。**改目录名会让它们看起来像合法的 v3 跑** ——
   那是把一个查不到出处的东西伪装成有出处的,比留着原名糟得多。
2. **格式太老**:2026-09-22 之前 `runner` 只往 `meta.json` 写一个 wrapper,
   上表那三个问题的答案**一个都没有**。

**数字不用它们,证据用。** 它们是「`direct` 在工具数据集上是无意义的筛子」
这个结论的来源。要引用 BFCL 的数就**重跑**,落进 `log/bfcl-v3-simple/`。

★ **为什么要单独写这一段**:一个「不可引用」的目录如果没有任何说明,
下一个人只会看到它、然后挑一个引用。**「这东西不能用」本身必须写在
能被找到的地方** —— 这是 §8.14 那条「删掉一个字段之后没有任何东西记得它来过」
在同一件事上的另一面。
